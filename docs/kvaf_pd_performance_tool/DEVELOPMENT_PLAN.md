# KVAF PD 性能分析与阶段耗时可视化工具开发计划

版本：v1.7 请求预热识别与正式请求筛选增补稿。日期：2026-11-13。

依据：[性能工具设计](DESIGN.md)。用户已授权逐步实现；本批本地代码、验证范围和未完成项见 [实现记录](IMPLEMENTATION_STATUS.md)，不提交或推送远端。
实施延续当前工作区，不新建分支或工作树，不覆盖用户原有修改。

## 1. 已确认范围

- 使用已有真实 PD 推理和请求发送工具，统计工具不产生负载。
- 正式统计仅纳入显式 measure 请求；客户端预热/探针、profiling 与未知用途排除，不按请求顺序或耗时猜测。
- 输入长度、目标输出长度、D 每卡目标 batch 可配置，实际值单独记录。
- 保留 t1/t2 的请求层样本（请求×层）、请求累计四组 mean/P90/P99/有效 N，增加请求阶段及端到端的同类统计。
- 重点实现请求阶段、里程碑和时间域；仅保留真实请求触发的 D block 分配/绑定与接收容量取得过程。
- 开发范围仅限真实请求的执行事件、里程碑、时钟关联和请求阶段耗时报表。
- 服务环境内运行独立分析脚本，直接在终端显示统计；按需汇总一个 Trace 文件，复制到 Windows 后展示交互阶段耗时。
- Trace 自包含所选事件、关联、统计摘要、配置与时钟质量；Windows 不依赖服务侧多份日志、CSV 或 checkpoint。
- 可插拔、默认关闭、性能影响尽量小，日志/缓冲可控，原推理和精度不得因采样而改变。
- 采样率、详细级别、事件缓冲和后台写盘可配置，按 DESIGN 第 3.3～3.4 节实现独立工具 JSON 契约。

实施以 DESIGN 第 1.1 节的已确认契约为准：只分析用户发出请求后的执行过程，时间轴画真实请求，统计面板同时给 mean、P90、P99 和有效 N。
请求层样本是一个请求在一层上一条路径的合并耗时；请求累计是各层之和；客户端端到端是发送到接收完成的实际跨度，三者不得互相替代。

**明确删除实例启动与初始化的全部性能需求。** 模型加载、通用 HBM/DDR 内存池预分配、MR 注册/导入、
通信建链/探测、图捕获和实例预热均无开发任务、hook、计时字段、采样开关、报表或性能验收。
只执行请求触发且可关联到请求 ID/代次或共享 batch 的观察任务；没有请求归属的事件不进入统计。
进程、资源和时钟标签只用于关联，不构成独立采集阶段，不追加注册、导入、探测或设备查询。

不重新讨论已确认的双 Pull、默认关闭和实际完成语义；未知源码事实由技术核对解决。
性能退化阈值、时钟同步容差、可获得的外部请求时间导出和实际采样预算在实施前落实，不编造默认验收通过值。

## 4. M2：最小采集插件

复用现有 Connector 对象级包装、有界队列和 checkpoint，补齐 span/parent、运行/进程代次、时钟域和采样质量字段。
统一请求级选择与阶段粒度，不将原始 Tensor、SDK 对象或整份请求元数据放入队列。
后台统一序列化和写盘，缓冲超限按配置丢弃新事件或停止本进程采集；磁盘失败和写盘总预算耗尽时停止采集并标记，不阻塞业务。
原异常和采集异常分开，原调用只执行原本需要的次数；关闭后无采样线程、文件和设备资源。
关闭路径必须在构造采集上下文和计时之前直接执行原操作，不在请求热路径读取配置、采样哈希、复制事件、排队或写日志。
新增用途头默认关闭；Proxy 未挂载 observer 时不读取该头。原返回对象、异常对象、同步/传输/RPC 次数及原重试行为均纳入验证。

按 DESIGN 第 3.3 节集中解析专用 JSON 文件，不向原生严格校验的业务配置插入未知参数，不新增环境变量或原生 CLI。
复用已有 `QUEUE_RECORDS`、`FLUSH_SECONDS`、`FILE_BUFFER_BYTES` 和 `CAPTURE_DIR` 的职责，改为读取有效配置，不维持重复的硬编码来源。
落实以下任务，所有默认值均为设计建议，后续需实测：

| 配置组   | 开发任务                                               | 完成依据                                                                         |
| -------- | ------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 采样率   | `enabled`、`sample_rate`、`sample_seed` 和稳定请求选择 | 默认关闭；`0` 不创建采集资源；`1` 全选符合筛选条件的请求；各端对同一请求选择一致 |
| 详细级别 | `stage` / `layer` / `detail`，默认 `layer`             | 粒度改变可采集事件，低档不为高档分配专用记录；缺少指标明确标不可用               |
| 事件缓冲 | `max_events`、`max_bytes`、`overflow_policy`           | 数量/字节上限同时生效；超限不阻塞、不自动扩容，被影响请求标为不完整              |
| 后台写盘 | 开关、目录、批量、flush 间隔、文件缓冲、单文件/总容量  | 后台限量处理；按实际字节分片；总预算耗尽停止；无隐式覆盖和无限重试               |
| 配置溯源 | 集中校验、默认值、配置快照、丢样及写盘计数             | 无效值明确拒绝；只影响采集能力；每轮固定配置，离线报告能还原实际生效值           |

`writer.enabled=false` 只保留有界内存和有限控制台计数摘要，不创建写盘线程/文件、不在退出时隐式落盘；无文件供独立脚本读取，不提供终端阶段分析或 Trace 导出。
整机采集内存和写盘预算按进程数汇总；事件缓冲上限不等于进程 RSS 上限。

完成条件：明确字段 schema、生命周期与预算；不增加 device sync、RPC、READ、payload 检查或业务状态依赖。
插件选择和关闭沿用现有 Connector module_path，采集参数来自专用 JSON；离线预检查不自动改用户脚本。

## 5. M3：请求阶段、里程碑和时间域

先落实 DESIGN 第 5 节各里程碑的可观察点和 host/device 计时依据，保留事件之间的真实依赖。
每个 span 带观察端和时钟域；区分客户端、Proxy/引擎、P/D Host、NPU device 与 K endpoint 调用方观察。
在阶段耗时中明确就绪、等待、实际执行和完成的差异，不按预设阶段顺序伪造线性过程。

增加本请求 D block 分配/绑定、P 调度/计算主机区间、发送排队、原生产完成等待、plan、Pull、D 请求内部处理、Commit/Publish、
接收完成汇总、D 实际调度和输出里程碑；覆盖共享 batch、chunk、贡献者与合法跳过。
保留原 pull_rpc 指标，同时实现有证据的允许发起口径；公共 plan 或锁区间共享关联，不能重复累计。
优先导入现有发送工具的实际发送/接收完成记录；无客户端证据时只展示服务端/局部跨度，不补造完整 E2E。

完成条件：请求/层/chunk/path 的完成确认与原业务一致；不把 Commit 之前的 CPU READ 完成当成 DDR 可读。
每个性能事件均须通过请求关联检查；本请求取得既有池资源的耗时不能扩展为通用资源的创建或注册耗时。
跨机入口或设备时间缺失时降级为局部指标，不称完整 E2E，不为了补证据新增同步或修改路由。

## 6. M4：服务环境内分析与单 Trace 导出

分析作为服务所在容器/服务器里的独立短期进程执行，不进入推理回调，不新增分析 API，不导入 NPU/SDK。
提供拟议 `summary` 入口：指定采集目录即可在终端显示四组核心统计、请求阶段分布、可得 E2E/TTFT 及质量摘要，默认不要求输出目录或先生成 HTML。
提供拟议 `export-trace` 入口：复用同一分析结果，将所选多源数据汇总到单个 `.trace.json`；保留现有统计命令兼容性。
两者只读稳定快照/可验证 checkpoint，不强制业务线程 flush；当前未完成尾部明确排除或标记，不据此宣称完整请求。

关联多机文件、别名和代次，验证重复拷贝、缺失 span、丢样、未结束及状态冲突。
沿用线性插值，按用户口径聚合贡献者/chunk/层/请求，分清累计、并集和墙钟跨度。
请求层样本、请求累计、每请求阶段、E2E 和可得 TTFT 分别同时输出 mean、P90、P99 和有效 N。
逐调用分布单独下钻，不让多 chunk/多 RPC 请求在请求阶段汇总中被重复加权。
复核 DESIGN 第 7.1 节的四个请求层样本和两个请求累计样本示意，确认有效 N 随统计粒度变化。
负载目标及实际值、batch 关联、endpoint 对比和时钟质量纳入终端摘要与 Trace 元数据；CSV/summary.json 仅按需额外生成。
采用 DESIGN 第 8.4 节的 Chrome Trace Event JSON 基础格式，包含标准事件区及版本化摘要、关联和时钟元数据。
导出集合和统计集合一致；未校准域保留原始事件，在配套查看器中单独显示本地时间，不伪造标准全局时间轴。
导出采用有界处理，超预算提示缩小范围或显式调整预算，不静默截断、不自动拆成多文件；成功后才发布完整目标文件。
用户提供已可访问的 P/D 与可得客户端/K 数据；缺少源只给对应局部结论，不自动登录其他服务器或新增业务控制通信。

完成条件：不以部分成功替代完整请求，不将阶段 P99 相加，不把父子 span 重复计入资源占比。
保存有效采样率、详细级别和配置快照，区分主动未采样、档位不覆盖与超限丢样；不通过采样率倒推分位数或有效 N。
没有可靠跨机时钟和依赖时，仅给局部阻塞链与不确定对齐，不输出伪精确关键路径。
相同快照/筛选下，终端统计与 Trace 摘要一致；仅复制一个 Trace 即可在 Windows 读取所选数据，无旁路服务器文件依赖。

## 7. M5：Windows 离线阶段耗时与报告

交付通用离线 HTML 查看器，由 Windows 浏览器选择或拖入单个 Trace，不要求安装 Python、vLLM、SDK 或连接推理服务。
验证 Chrome Trace/Perfetto 类通用工具对标准事件区的兼容性；完整统计面板和未对齐时钟域由配套查看器提供，不宣称通用工具支持所有扩展元数据。
形成请求执行阶段耗时：缩放、平移、筛选、层/chunk/贡献者折叠、里程碑标记、因果连线、等待分类和点击详情。
增加 mean/P90/P99 阶段图、t1/t2 四组统计及真实 P50/P90/P99 附近请求选择。
界面包含真实请求时间轴、统计面板和详情区；span 为持续动作，里程碑为点/竖线，不将平均值或阶段 P99 拼成请求轨迹。
查看器资源离线自包含，数据来自一个 Trace；在内存中按请求建立索引并按需展开，不依赖本地多分片数据服务或 CDN。
已对齐域展示公共轴，未对齐域展示明确分开的本地轴；验证选择文件、较大单文件与浏览器内存限制。
CSV/JSON 明细按需导出，图表支持选区 SVG/PNG；明确单位、观察来源、时钟误差、样本量和完整性。

完成条件：图中的色块来自实际事件，不生成虚构测量值或用统计分位数拼接假请求。
大规模记录不会一次渲染全部 DOM，缺失数据与未知内部阶段可见。

## 8. M6：验证与性能影响验收

### 8.1 轻量检查

复用现有分析工具和适用的 CPU/mock 检查，不新增 UT/test 文件，不修改业务测试来适配采样结果。
对实际变更做必要语法、格式、数据契约、去重、范围和生命周期检查；使用临时内存数据验证统计，不伪装硬件采样。
文档中的例子始终注明示意；未运行的 NPU/UB、图模式和精度检查明确列出。
复核 `0`/`1` 采样率、固定 seed、未知字段/枚举、非有限数、非正容量、跨字段约束及配置文件缺失行为。
验证两端选择一致、三档覆盖范围、事件数/字节任一触顶、低流量定时 flush、分片/总预算、写盘关闭及错误停用。
验证终端与 Trace 摘要一致、导出筛选重算、半写尾部快照、单文件缺失/未校准时钟域及损坏/超预算 Trace 的明确提示。
对 `enabled=false`、`sample_rate=0` 分别使采集工厂、计时器、回调和上下文构造一旦被调用就失败，复用原传输字节、分段、完成回执丢失及异常检查验证关闭短路。

### 8.2 真实 A/B

使用用户现有请求发送工具，在相同配置与负载下交替执行原 Connector 和采样 Connector，建议至少三轮。
单独对照原入口与工具入口关闭采集的路径；默认关闭无性能退化须由实机请求指标证明，不能用“无采集文件”替代吞吐/时延与精度验证。
两端关闭字节诊断和额外 profiler，保证所选请求集合、输入/输出、并发和实际 batch 可对照。
对采样率、详细级别、缓冲和写盘参数的代表组合记录真实开销；不把某一组合的结论推广到所有配置，低采样量明确显示 P99 的有效 N。
记录吞吐、TTFT/TPOT/E2E 分布、请求成功率、CPU/RSS/磁盘/HBM 和长期增长趋势。
对同请求、seed、采样、拓扑、MTP 的输出/可得 token IDs 做精度对照，先识别基线自身波动。
超出预先记录的退化门槛或出现新输出分歧时，不作为低开销无精度影响工具交付，继续定位或降低采样粒度。

### 8.3 故障与退出

检查队列满、写盘失败、超预算、进程退出、重复/缺失事件、Pull 异常、取消与原路径恢复。
采样故障只影响证据完整性，不额外重试业务、不覆盖异常、不释放仍在 DMA 使用的对象。
停止采样及后台 flush 有界，不在持有 Runtime/源组业务锁时等待写盘，不以采样退出强制关闭 SDK。
恢复原 Connector 配置后，用真实请求验证原路径与资源行为，不遗留默认启用的观测代码或文件消费者依赖。
